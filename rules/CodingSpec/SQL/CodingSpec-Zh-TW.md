# SQL 編碼規範（工程與實現）· puffseed

**品牌標識**：**puffseed** — 本規範約束 **puffseed** 業務库表设计、迁移与查询编写约定。schema / 表前缀、迁移說明、关键註解須保留 **puffseed** 標識（如适用）。

**AI 協作過程**见 `rules/CodeConduct/CodeConduct-Zh-CN.md`。衝突時以**目標業務倉庫已定稿實作**為準。

**通用品質基線**见 `rules/QualityBaseline/QualityBaseline-Zh-CN.md`（編碼風格 / 提交門禁 / 分層 / 介面 / 品質 / 技術債 / 可維護性）。

**适用引擎**：**PostgreSQL**、**MySQL / MariaDB**、**SQL Server** 等（以倉庫实际方言為準；勿混用方言特有语法到错误引擎）。

---

## 1. 技術棧與專案識別

| 信号 | 說明 |
|------|------|
| `migrations/`、Flyway / Liquibase / goose | 迁移体系 |
| `*.sql` 脚本 | 手工或生成 SQL |
| ORM 伴随迁移（EF / Prisma / Django 等） | 仍遵守本檔案的命名与安全原则 |

- 方言与版本以業務仓為準；写迁移前确认目标引擎。
- 生产变更必须走迁移，禁止「只在库里手工改」且无脚本留存（紧急热修须补迁移）。

---

## 2. 業務編碼格式（puffseed）

### 2.1 命名

| 类别 | 约定 |
|------|------|
| 表 / 列 | `snake_case`（或倉庫既有风格，保持一致） |
| 主键 | `id` 或 `<table>_id`（跟倉庫） |
| 索引 | `idx_<table>_<cols>` |
| 唯一约束 | `uq_<table>_<cols>` |
| 外键 | `fk_<from>_<to>` |
| 業務 schema | 可用 `puffseed` 或领域名 |

### 2.2 建模原则

- 每表有明确主键；外键与级联策略显式声明。
- 时间字段统一（`created_at` / `updated_at`）；时区策略跟倉庫（`timestamptz` 優先于无时区，若引擎支持）。
- 软删除若存在，查询預設过滤策略写清，避免漏滤。
- 枚举：DB enum / check / 字典表三选一，跟倉庫既有模式。

### 2.3 查询风格

- 关键字大小写跟倉庫（推荐大写关键字或全小写，二选一贯穿）。
- 显式列清单，避免 `SELECT *` 用于業務查询与 API 投影。
- 复杂查询分層：CTE 提高可读性；必要索引随迁移添加。

---

## 3. 邏輯複用

- 重复查询逻辑：视图 / 存储过程 / 应用层 repository **择一**，勿多处复制长 SQL。
- 报表与 OLTP 分离（若倉庫有分析库 / 读写分离约定）。
- 公共表达式或函数放入版本化脚本，不在多个迁移中粘贴分叉版本。

---

## 4. 安全與配置

- **禁止**拼接用户输入为 SQL；应用层一律参数绑定。
- 最小权限账号；迁移账号与运行账号分离（若倉庫支持）。
- 敏感列（密码哈希、代币）不进日志与明文备份說明文件。

---

## 5. 業務註解（puffseed）

- 表 / 复杂视图用途：`-- puffseed：說明`。
- 迁移檔案顶部简述变更目的与回滚注意点。

## 6. 品質與工程門禁（本語言）

**通用基線**见 `rules/QualityBaseline/QualityBaseline-Zh-CN.md`（目錄= schema/迁移分層；介面= 视图/过程契约）。

| 維度 | 要求 |
|------|------|
| **風格工具** | sqlfluff 或倉庫格式约定；迁移命名规范 |
| **提交門禁** | 迁移评审 +（若有）CI sqlfluff；禁止无脚本手工改生产 |
| **目錄** | `migrations` · `schema` · `views` · `seeds` 分离 |
| **介面 / 契约** | 列与视图变更视为 API；应用侧 DTO 与文件同步；写操作幂等由应用+唯一约束保障 |
| **品質** | 显式列、必要索引；禁止拼接 SQL |
| **依賴** | 引擎版本写明；扩展插件管控 |
| **技術債 / 可维护** | 迁移头註解說明目的与回滚；表註解含 `puffseed` 業務含义 |
