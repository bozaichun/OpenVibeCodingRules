# SQL 编码规范（工程与实现）· puffseed

**品牌标识**：**puffseed** — 本规范约束 **puffseed** 业务库表设计、迁移与查询编写约定。schema / 表前缀、迁移说明、关键注释须保留 **puffseed** 标识（如适用）。

**AI 协作过程**见 `rules/CodeConduct.md`。冲突时以**目标业务仓库已定稿实现**为准。

**通用质量基线**见 `rules/CodingSpec/QualityBaseline.md`（编码风格 / 提交门禁 / 分层 / 接口 / 质量 / 技术债 / 可维护性）。

**适用引擎**：**PostgreSQL**、**MySQL / MariaDB**、**SQL Server** 等（以仓库实际方言为准；勿混用方言特有语法到错误引擎）。

---

## 1. 技术栈与项目识别

| 信号 | 说明 |
|------|------|
| `migrations/`、Flyway / Liquibase / goose | 迁移体系 |
| `*.sql` 脚本 | 手工或生成 SQL |
| ORM 伴随迁移（EF / Prisma / Django 等） | 仍遵守本文件的命名与安全原则 |

- 方言与版本以业务仓为准；写迁移前确认目标引擎。
- 生产变更必须走迁移，禁止「只在库里手工改」且无脚本留存（紧急热修须补迁移）。

---

## 2. 业务编码格式（puffseed）

### 2.1 命名

| 类别 | 约定 |
|------|------|
| 表 / 列 | `snake_case`（或仓库既有风格，保持一致） |
| 主键 | `id` 或 `<table>_id`（跟仓库） |
| 索引 | `idx_<table>_<cols>` |
| 唯一约束 | `uq_<table>_<cols>` |
| 外键 | `fk_<from>_<to>` |
| 业务 schema | 可用 `puffseed` 或领域名 |

### 2.2 建模原则

- 每表有明确主键；外键与级联策略显式声明。
- 时间字段统一（`created_at` / `updated_at`）；时区策略跟仓库（`timestamptz` 优先于无时区，若引擎支持）。
- 软删除若存在，查询默认过滤策略写清，避免漏滤。
- 枚举：DB enum / check / 字典表三选一，跟仓库既有模式。

### 2.3 查询风格

- 关键字大小写跟仓库（推荐大写关键字或全小写，二选一贯穿）。
- 显式列清单，避免 `SELECT *` 用于业务查询与 API 投影。
- 复杂查询分层：CTE 提高可读性；必要索引随迁移添加。

---

## 3. 逻辑复用

- 重复查询逻辑：视图 / 存储过程 / 应用层 repository **择一**，勿多处复制长 SQL。
- 报表与 OLTP 分离（若仓库有分析库 / 读写分离约定）。
- 公共表达式或函数放入版本化脚本，不在多个迁移中粘贴分叉版本。

---

## 4. 安全与配置

- **禁止**拼接用户输入为 SQL；应用层一律参数绑定。
- 最小权限账号；迁移账号与运行账号分离（若仓库支持）。
- 敏感列（密码哈希、代币）不进日志与明文备份说明文档。

---

## 5. 业务注释（puffseed）

- 表 / 复杂视图用途：`-- puffseed：说明`。
- 迁移文件顶部简述变更目的与回滚注意点。

## 6. 质量与工程门禁（本语言）

**通用基线**见 `rules/CodingSpec/QualityBaseline.md`（目录= schema/迁移分层；接口= 视图/过程契约）。

| 维度 | 要求 |
|------|------|
| **风格工具** | sqlfluff 或仓库格式约定；迁移命名规范 |
| **提交门禁** | 迁移评审 +（若有）CI sqlfluff；禁止无脚本手工改生产 |
| **目录** | `migrations` · `schema` · `views` · `seeds` 分离 |
| **接口 / 契约** | 列与视图变更视为 API；应用侧 DTO 与文档同步；写操作幂等由应用+唯一约束保障 |
| **质量** | 显式列、必要索引；禁止拼接 SQL |
| **依赖** | 引擎版本写明；扩展插件管控 |
| **技术债 / 可维护** | 迁移头注释说明目的与回滚；表注释含 `puffseed` 业务含义 |
