03 / Quick Start

快速开始

把规范拷进业务仓，告诉 AI 按 AGENTS 编码，再按语言加载规则。

STEP 01

复制到业务项目

将 AGENTS.md 与 rules/ 放到项目根目录，保持相对路径。

demo/
├── AGENTS.md
├── rules/
│   ├── CodeConduct.md
│   └── CodingSpec/
│       ├── QualityBaseline.md
│       ├── JavaScript&TypeScript/
│       └── …/
└── src/
STEP 02

前端引入 WebVariable

不要复制 Token 源码，只在入口按序引入：

ThemeVariable.css
→ SystemVariable.css
→ ProjectReset.css
→ 应用级 CSS

路径： rules/CodingSpec/JavaScript&TypeScript/WebVariable/

STEP 03

在 Cursor 中启用

  1. 根目录保留 AGENTS.md
  2. CodeConduct.md 默认 alwaysApply
  3. 按任务 @ 引用语言 CodingSpec
  4. UI 任务再加 DESIGN / WebVariable

向 AI 发起任务时建议写明：请根据 AGENTS.md 进行编码开发；先识别语言与技术栈，再编码。

04 / AI Context

AI 应加载哪些规范

按任务最小加载，节约 Token，避免无关规则干扰。

任务类型 应加载 通常不必加载
任意起步 AGENTS.md · CodeConduct.md 其他语言 CodingSpec
任意业务代码 + QualityBaseline.md + 对应语言 CodingSpec.md 无关语言规范
前端 UI / 样式 + DESIGN.md · WebVariable PreView HTML 全文
改主题色 / 间距 ThemeVariable.css / SystemVariable.css —
深浅色视觉验收 浏览器打开 PreView 勿将 HTML 喂给 AI

05 / Quality

质量基线（全语言）

详见 QualityBaseline.md ；各语言 CodingSpec 另有「质量与工程门禁」落点。

1. 代码规范

  • 命名 · 注释 · 格式统一
  • ESLint / Prettier / 阿里 P3C 等按语言启用
  • 提交阶段强制校验
  • 目录分层：控制 / 业务 / 数据 · 公共 · 工具 · 类型 · 配置
  • 接口信封 · 错误码 · HTTP · 幂等 · 版本 · 文档同步

2. 代码质量

  • 高内聚低耦合，三层职责清晰
  • 模块化复用，减少重复
  • 强类型 · 参数校验 · 空值 / 异常边界
  • lockfile + 依赖漏洞扫描
  • 技术债登记，禁止无主临时代码

3. 可维护性

  • 代码可读，关键路径有注释
  • 业务注释保留 puffseed 标识
  • README 写清启动与目录地图
  • 新人可快速上手主路径

07 / Workflow

开发前识别流程

01

识别语言 / 框架

看依赖与入口：如 vue、fastapi、Cargo.toml、pubspec.yaml 等。

02

前端再判项目模式

无 public/plugin.json → 普通项目；存在 → uTools 插件（仅 React / Vue）。

03

按最小集加载规范

CodeConduct + QualityBaseline + 语言 CodingSpec；（UI）再加 DESIGN / WebVariable。

08 / FAQ

常见问题

可以把 WebVariable 复制到 src/styles/ 吗？

不建议。应通过入口 import / <link> 引用，保证 Token 单一维护源。

后端也要 WebVariable 吗？

不需要。后端加载 QualityBaseline 与对应语言 CodingSpec.md 即可。

AI 没有遵守规范怎么办？

显式 @AGENTS.md、@QualityBaseline.md 与对应语言 CodingSpec.md；任务中写明「遵循 OpenVibeCodingRules / puffseed，最小 diff」。
